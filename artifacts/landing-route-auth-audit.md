# 落地页登录逻辑审核

审核日期：2026-09-03

## 实施更新（2026-09-03）

落地页已统一为轻量路由级保护：

- 根布局接入 `RouteAuthGate`，业务页面在通过登录判断前不挂载。
- 受保护范围：AI、专家 AI、测评、报告、资料、资料预览、预约、我的预约、客服、资料补充、签到、沙龙投票。
- 公开范围：首页、登录页、微信登录回调、税收分类编码。
- 本地已有 token 时直接进入，不为每次路由跳转重复调用 `/api/auth/me`。
- 本地无 token 时调用一次认证恢复，兼容开发环境 `AUTH_BYPASS_ENABLED`；恢复失败才弹出登录。
- API 返回 401、`AUTH_REQUIRED` 或 `*_AUTH_REQUIRED` 时清理 token，并通知路由守卫阻断当前页面。
- 登录弹窗关闭后返回安全 `returnTo`，否则返回首页。

验证：62 个测试通过，TypeScript 通过，Next.js 生产构建成功。项目 lint 脚本因未安装 ESLint 无法执行。

## 结论

落地页当前采用的是“来源入口保护 + 页面内操作保护”的混合模式，**不等同于**“进入任何业务页面前必须完成登录”。

- 从落地页首页点击 AI、测评、资料、客服、预约、签到时，会先执行 `requireLogin`，登录成功后才跳转。
- 但是大多数目标业务 URL 没有路由级保护。用户直接访问 URL 时，可以先看到业务页面，直到点击提问、开始测评、领取、签到或提交时才要求登录，或者直接收到 API 的 401 错误。
- 只有 `/profile/complete` 和 `/appointment/my` 接近严格的目标路由保护：未登录时会跳转到登录页。

## 首页入口逻辑

`components/mobile/event-landing-page.tsx` 中的 `requireLogin(action)` 会保存待执行动作并打开 `LoginModal`，登录成功后再执行跳转。

已通过首页入口保护的业务：

- `/tax-ai`
- `/risk-assessment`
- `/materials`
- `/support`
- `/appointment`
- `/checkin`
- 活动报名
- 首页资料领取

这一层符合“未登录不从首页进入业务页”。

## API 层

后端对 AI、预约、测评提交、报告、资料查看、资料领取、签到和投票等接口进行了登录校验。这可以防止匿名写入或读取受保护数据，但不能替代前端路由守卫。

严格规则要求：

1. 未登录时不渲染目标业务页面。
2. 未登录时不启动目标页面的业务 API 请求。
3. 登录成功后再挂载目标页面并恢复原路径。
4. 直接访问、刷新、分享链接和站内导航采用同一规则。

## 审核时判断（实施前）

落地页目前只有“从首页正常点击”的主路径基本符合要求；从直接 URL、刷新和分享链接进入时不符合。因此不能把落地页现有实现直接作为小程序路由鉴权标准。

如果产品规则已经确定为“业务页面未登录压根进不来”，则落地页和小程序都应统一改为路由级登录保护。

上述问题现已由本报告顶部“实施更新”所述的统一路由守卫解决。

审核状态：`safe-general-engineering`。

推荐下一步：使用统一的 Protected Route/Auth Gate 同时规范落地页和小程序，再使用 `wechat-miniprogram-validate` 验证小程序所有直接路由入口。
