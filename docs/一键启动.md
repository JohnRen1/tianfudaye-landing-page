# AI 问答本地一键启动

本文记录本地同时启动落地页、Agent、法规 RAG 和 Qdrant 的常用命令。
当前固定采用 **V1 Agent（0.3.0）+ V2 RAG**。Agent V2 暂时停用，保留源码用于历史参考；未经重新确认，不切回 V2 Agent。

默认 Agent 源码为相邻目录 `税务Agent客服-v1-local`，镜像为 `tax-agent-service:v1-agent-v2-rag-local`。
已有镜像时直接复用；没有镜像时才从 V1 源码首次构建。启动前核验源码和镜像实际版本，启动后核验 `/health` 的 Agent 版本与 RAG 集合。

当前脚本会按顺序启动：

1. 法规 Qdrant
2. 法规 RAG API
3. V1 税务 Agent API
4. 落地页 Next.js dev 服务

## 一键启动

### 独立测试界面（无需进入网站）

打开 Docker Desktop 后执行：

```bash
cd "/Users/renxubin/Desktop/工作/主业务/拓客系统-落地页"
pnpm run tax-ai:test
```

直接访问 `http://127.0.0.1:8788`。此模式只启动 Qdrant、V2 RAG、V1 Agent 和独立测试页；不启动 Next.js，不需要网站登录、短信验证码或落地页 `.env.local`。

界面支持连续对话、真实流式回答、引用展示、新会话和 JSON 导出。密钥只在测试页服务端使用。
实际回答仍来自原有 V1 Agent `/chat`；服务未连接、版本不符或流式回答中断会明确显示，不会生成模拟答案。

原本的 `pnpm run tax-ai:down/status/logs` 同样管理独立测试页。
如果只想打开界面检查连接，也可在 V1 Agent 目录执行 `.venv/bin/python scripts/local_chat_test.py`；它只运行网页，不会自动启动问答后端。

### 完整落地页

```bash
cd "/Users/renxubin/Desktop/工作/主业务/拓客系统-落地页"
pnpm run tax-ai:up
```

不再需要每次设置 `TAX_AGENT_ROOT` 和 `TAX_AGENT_IMAGE`。先打开 Docker Desktop 即可启动本地测试。

不启动服务、只检查本地配置：

```bash
pnpm run tax-ai:check
```

修改 V1 Agent 源码后，需要明确重建镜像：

```bash
TAX_AGENT_SKIP_BUILD=0 pnpm run tax-ai:up
```

沿用旧的 V2 Agent 目录、`0.4.0` 或 `v2-*` 镜像启动命令会被拒绝；即使 V1 标签误指向 V2 镜像，也会在启动服务前停止。

启动完成后访问：

```text
http://127.0.0.1:3000/tax-ai
```

启动完成后脚本会自动进入 RAG API、税务 Agent 和落地页日志跟随模式。按 `Ctrl+C` 只退出日志查看，不会停止服务；需要再次查看日志时可执行 `pnpm run tax-ai:logs`。

专家问答入口：

```text
http://127.0.0.1:3000/tax-ai-pro
```

如果登录手机号存在于数据库表 `tax_ai_expert_users` 且 `is_active=true`，访问 `/tax-ai`
会自动进入 `/tax-ai-pro`。该表由 supabase 项目迁移文件
`/Users/renxubin/Desktop/工作/主业务/supabase/migrations/20260810140000_create_tax_ai_expert_users.sql`
维护。

专家提交的审阅记录会写入 `qa_expert_reviews`，对应迁移文件为
`/Users/renxubin/Desktop/工作/主业务/supabase/migrations/20260810141000_create_qa_expert_reviews.sql`。
当前管理后台还没有单独的专家审阅列表页，后续如需人工查看审阅版本，需要在管理后台增加对应页面或直接查表。

## 启动前提

启动前请确认以下文件已存在且内容正确：

```text
/Volumes/renxubin/税务法规RAG/.env
/Users/renxubin/Desktop/工作/主业务/税务Agent客服-v1-local/.env
/Users/renxubin/Desktop/工作/主业务/拓客系统-落地页/.env.local
```

同时确认：

- Docker 已启动
- `pnpm install` 已完成
- `uv sync` 已完成
- 三个项目中的接口密钥已对齐
- RAG `.env` 的 `COLLECTION_NAME` 为 `tax_regulations_v2_20260901`（或后续已确认的 V2 集合）；不能继承指向 V1 的 `COLLECTION_NAME` 进程环境变量。
- 外部信息搜索保持关闭。V1 Agent 使用模型 API 和本地 V2 RAG，RAG 内容由维护者手动更新。
- 手机扫码本地二维码时，手机和电脑需要处于同一局域网；启动脚本会绑定 `0.0.0.0`，允许局域网访问。
- 管理后台 `.env.local` 的 `PUBLIC_LANDING_PAGE_URL` 必须使用当前电脑的局域网 IP，例如 `http://192.168.0.133:3000`，不能使用 `localhost` 或 `127.0.0.1`。

## 本地调试说明

如果一键启动失败，优先检查这几项：

1. 落地页 `.env.local` 中的 `RAG_CHAT_URL` 是否指向 `http://127.0.0.1:8003/chat`
2. Agent `.env` 中的 `RAG_BASE_URL` 是否指向 `http://host.docker.internal:8010`
3. 法规 RAG `.env` 中的 `QDRANT_URL` 是否指向 `http://127.0.0.1:6335`
4. `TAX_AGENT_API_KEY` 与 `AGENT_API_KEY` 是否一致
5. `RAG_API_KEY` 与法规 RAG 的 `RAG_API_KEY` 是否一致

## 人工测试与后续云端更新

本轮调整本地启动流程；云端上传和切换由维护者在人工测试通过后执行。
后续准备云端 Agent 构建时，构建上下文应使用 `税务Agent客服-v1-local`，不能误用仍保留的 V2 主目录。

建议在同一会话连续提问：

1. 员工退休，公司需要怎么处理？
2. 公司不再返聘，请给我一份办理清单。
3. 如果退休后偶尔回来做顾问，需要补充考虑什么？

另开一组测试发票问题，检查回答、引用和上下文：

1. 员工报销差旅费，收到代理机构开的“经纪代理服务*代订机票”普通发票，能否抵扣进项税？
2. 这张票只收取代理费，机票费用另有行程单，需要分开处理吗？
3. 请整理成财务可以执行的核对清单。

保存实际回答和引用供人工复核；代码测试、健康检查不能替代财税回答质量验收。

## 表格滚动验证问题

如果需要验证 AI 回答中的 Markdown 宽表是否可以左右滑动，可以在页面输入：

```text
请生成一个 Markdown 表格，列名分别是：事项名称、适用主体、发生时间节点、合同条款关注点、发票处理、账务处理、增值税影响、企业所得税影响、个人所得税影响、社保影响、资料清单、人工确认建议。内容用赊销业务收入确认举例。
```

期望表现：

- 表格在消息气泡内横向滑动查看。
- 页面整体不出现横向滚动。
- 底部输入框不被撑宽。
- “联系人工客服”按钮位置正常。
