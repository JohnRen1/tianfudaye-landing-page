# 普通用户历史对话

## 当前对话与切换规则

- 历史列表包含已经保存的当前对话，按进入历史页前的 session 标注“当前对话”，点击可返回继续编辑。直接进入历史页时不推测当前会话。
- 打开其他历史会话保留原业务返回入口和活动归因；用 replace 返回问答，避免反复往返堆积历史页。
- 切换前显式保存会话草稿。新建空会话不增加服务器历史记录；原会话草稿仍留在原会话缓存。
- 无 session_id 的旧记录恢复时保留 record:<id> 作为缓存标识；追问产生新 sessionId 后同步地址与新会话缓存，避免重新进入只剩旧记录。
- 历史分页失败时只允许重试当前页，不能跳页；历史加载错误不显示为“没有历史”。

- `/tax-ai/history` 按会话展示第一问标题、最后一问预览、更新时间和轮数，每页 20 个会话。
- `/tax-ai?session=...` 从数据库恢复消息，沿用原 sessionId 追问；发送给 Agent 的近期上下文仍为最近 10 条消息。
- 顶部“新对话”在至少完成一轮问答后生成新 UUID，不删除历史；首次只有草稿时按钮保持禁用，避免误丢正在编辑的问题。空会话不会写入数据库。草稿仅保存在当前标签页，按经过服务端验证的用户 ID 和会话 ID 隔离；浏览器返回可恢复草稿。
- 生成回答、录音、转写期间禁止按钮切换会话。加载失败时禁止发送，允许重新加载。
- 普通用户完整问答仍由现有 POST `/api/ai/chat` 自动保存。专家模式保持原流程，不提供普通用户历史入口。

## 查询契约及权限

GET `/api/ai/history?page=1` 返回 `{items: [{sessionId,title,preview,updatedAt,turns}],hasMore}`。
GET `/api/ai/history?session=...` 返回按时间及 ID 排序的 `{id,question,answer,createdAt}[]`。
响应使用项目统一 success/data 包装。未登录 401、参数错误 400、会话不存在或不属于用户 404、查询失败 500。

两个查询始终使用登录态 userId 筛选；不接受客户端用户身份。没有 session_id 的历史单条记录以 `record:<id>` 展示，读取时额外要求 session_id 为空，后续追问开启新会话并传递已恢复上下文。

使用现有 qa_records，无 schema 或 RLS 变更，也没有 Mock 替换。服务端 Service Role 查询依靠显式 user_id 条件隔离用户。
列表分批读取当前用户的元数据后分组，详情分批读取避免数据库默认行数上限截断。若单用户积累大量记录，应通过 migration 增加聚合查询或会话表；当前版本每次列表请求扫描该用户全部问答元数据。

## 验证

自动测试覆盖分组与排序、分页、身份隔离、参数验证和数据库异常。
人工验收：完成两轮问答 → 新对话 → 历史列表 → 打开旧会话追问；在旧会话输入未发送草稿后切换，再通过浏览器返回检查草稿。测试不应向生产数据写入虚构问答。
